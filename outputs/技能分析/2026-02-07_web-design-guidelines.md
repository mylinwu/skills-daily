## 1. 技能用途

这是一个**UI代码审查工具**，帮助开发者检查前端代码是否符合 Vercel 的 Web Interface Guidelines 最佳实践。

### 适用场景

当用户提出以下请求时触发：

- "review my UI"（审查我的UI）
- "check accessibility"（检查可访问性）
- "audit design"（审计设计）
- "review UX"（审查用户体验）
- "check my site against best practices"（对照最佳实践检查我的站点）

### 核心价值

- **自动化设计审计**：将人工设计审查流程自动化，节省设计师和开发者的时间
- **标准化检查**：基于 Vercel 团队的成熟设计规范，确保UI质量
- **可访问性保障**：检查 WCAG 等无障碍标准合规性
- **持续改进**：每次审查都从 GitHub 获取最新指南，规则保持最新

## 3. 作用机制分析

### 核心工作原理

```
┌─────────────┐     ┌──────────────────┐     ┌─────────────┐
│  用户请求   │ ──→ │ 获取最新指南规则  │ ──→ │ 读取目标文件 │
└─────────────┘     └──────────────────┘     └─────────────┘
                                                        ↓
┌─────────────┐     ┌──────────────────┐     ┌─────────────┐
│ 输出报告    │ ←── │  应用规则检查    │ ←── │  代码分析   │
└─────────────┘     └──────────────────┘     └─────────────┘
```

### 运行机制详解

**第一步：动态获取指南**

技能不内置规则，而是从远程仓库实时拉取：

```
https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md
```

这种设计的优势：

- 规则可随时更新，无需重新安装技能
- 社区驱动的持续改进
- 始终使用最新的设计标准

**第二步：文件匹配与读取**

- 接受 `<file-or-pattern>` 参数（如 `*.tsx` 或具体文件路径）
- 如用户未提供，主动询问要审查的文件
- 读取所有匹配文件的内容作为审查上下文

**第三步：规则应用与检查**

根据获取的 guidelines 内容，对代码进行多维度检查：

- 可访问性（ARIA标签、键盘导航、对比度）
- 用户体验（交互反馈、加载状态、错误处理）
- 视觉设计（一致性、间距、排版）
- 性能（图片优化、懒加载）

**第四步：结果输出**

采用简洁的 `file:line` 格式输出发现的问题，便于开发者快速定位和修复。

### 提示词引导策略

技能通过以下机制引导 AI 行为：

1. **明确的触发词**：在描述中列出5个常见触发短语，确保在合适场景被激活
2. **结构化工作流**："How It Works" 部分提供清晰步骤，规范 AI 的执行顺序
3. **外部规则引用**：不硬编码规则，而是引用权威来源，保持灵活性和权威性
4. **格式规范**：明确指定输出格式（`file:line`），确保结果的可读性和可操作性
