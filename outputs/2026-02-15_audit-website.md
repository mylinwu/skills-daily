# audit-website 技能分析报告

## 1. 技能用途

`audit-website` 是一个面向网站健康检查的自动化审计技能，核心能力是调用 `squirrel` CLI 对站点进行抓取、分析并输出可读报告。

它适合用于以下场景：

- SEO 体检：检查标题、描述、canonical、结构化数据、Open Graph 等
- 技术质量排查：发现死链、重定向链、可抓取性问题、URL 结构问题
- 性能与体验改进：发现页面加载、移动端、可访问性、可用性问题
- 安全与合规检查：识别 HTTPS、安全头、潜在泄露信息、隐私与法律类缺失
- 持续优化闭环：修复后复扫，对比前后分数和问题变化

从 `SKILL.md` 可见，该技能覆盖 21 类问题、230+ 规则，并支持按严重级别（error/warning/notice）与优先级（rank）进行处理。

## 3. 作用机制分析

这个技能本质是“命令编排 + 修复闭环”的方法论，而不是单一命令。

### 3.1 三段式执行内核

技能将网站审计拆分成三步，并可由 `audit` 一键封装：

1. `crawl`：抓取页面与站点结构
2. `analyze`：按规则集进行检测
3. `report`：输出报告（推荐 `--format llm`）

其中 `squirrel audit <url> --format llm` 是最常用入口，适合 AI 直接消费。

### 3.2 结果驱动的迭代闭环

`SKILL.md` 明确了标准流程：

1. 展示报告与评分
2. 提出可修复项并等待用户确认
3. 对可并行问题批量修复
4. 重新审计并对比分数变化
5. 继续下一轮直到达到目标或只剩需人工判断的问题

这使技能具备了“诊断 -> 修复 -> 验证 -> 再优化”的持续改进能力。

### 3.3 覆盖模式与成本控制

技能通过 `--coverage` 管控审计深度：

- `quick`：快速健康检查（CI/日常巡检）
- `surface`：默认模式，按 URL 模式抽样，效率高
- `full`：深度覆盖，适合上线前或全面治理

这种模式分层降低了审计成本，也让“先快扫、后深扫”的策略更可执行。

### 3.4 并行修复策略

技能强调把“可并行内容修复”与“需人工判断事项”分开：

- 可并行：alt 文本、标题层级、短描述、HTTP 链接替换等
- 需人工判断：断链去留、结构性改动、语义与业务决策

这减少了自动化误改风险，也提升了整体修复效率。

### 3.5 关键价值总结

`audit-website` 的核心价值不只是“扫出问题”，而是提供了一套可落地的治理框架：

- 规则覆盖广，问题发现全面
- 输出结构适合 LLM 消费与二次加工
- 支持回归对比（diff/regression）
- 能把网站质量优化变成可重复的工程流程

对于需要长期维护 SEO、技术质量与内容质量的团队，这个技能具备较高实用性。
